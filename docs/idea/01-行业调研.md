# 行业调研（方案初稿）

> idea 阶段文档。基于公开行业常识＋《服务数字人 PRD》语境整理，**非付费调研报告**；结论待业务补一手数据。  
> **2026-10-02 勘误**：本项目现行业务线为**零售金融客服数字人**（非泛电商售后）。下文「客服」均按金融客服理解；电商样例仅作历史联调参考。

## 1. 调研目的

判断「金融数字人客服＋大模型 Agent」是否值得在现有 jtalk 体系上演进，以及主要技术、合规与组织门槛。

## 2. 市场与需求趋势（摘要）

| 趋势 | 对项目含义 |
| --- | --- |
| 客服成本与体验双压 | 数字人用于提升感知与引导，不能替代稳定解决率 |
| 多模态交互普及 | 用户接受「听＋看」；失败必须回图文／人工 |
| 大模型进入客服编排 | 适合作「应答编排／摘要／路由建议」，不适合作无约束执行器 |
| 合规趋严 | 录音影像、个人信息、披露「非人工」成标配讨论点 |

## 3. 技术栈分层（行业常见）

1. 触点：App／H5／小程序客服容器  
2. 会话与路由：机器人／人工／数字人呈现  
3. 认知：FAQ／NLP／LLM Agent／RAG  
4. 媒体：TTS、驱动、RTC／流媒体  
5. 运营：话术、分流、质检、评价  

本项目选择：**复用 1–2、4 现网能力，增强 3，换肤 1 的 UI**。

## 4. 关键门槛

- 音视频稳定性与并发 Room 成本  
- 口播与图文同步、打断体验  
- 幻觉与错误承诺风险  
- 多团队协作（客服产研×数字人×算法）  

## 5. 初步结论

适合作为 **现网增强型方案** 立项做方案与可选 POC；不适合从零自研全栈数字人引擎（与「人力有限」一致）。
