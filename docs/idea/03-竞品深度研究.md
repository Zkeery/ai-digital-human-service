# 竞品深度研究（1 份｜方案初稿）

> 《项目文档》要求深度研究报告 → **1 个**。对象选定：**「平台内嵌数字人客服」品类**（以会话容器＋数字人蒙层＋机器人分流为代表），对照本项目基线（jtalk＋数字人）。  
> 无付费竞品账号实测时，结论标为**二手／推演**，待补证。

## 1. 研究对象定义

「在已有在线客服中，用数字人形象播报机器人答案，并支持转人工」的产品形态，而非独立陪伴数字人 App。

## 2. 典型能力地图

| 能力 | 常见做法 | 本项目基线 | 差距／机会 |
| --- | --- | --- | --- |
| 入口分流 | 活动页／FAQ 标记／灰度开关 | 入口＋FAQ 标记 | 保持 |
| 呈现 | 全屏数字人＋半屏对话 | 蒙层＋答案蒙层 | UI 可换肤 |
| 同步 | 音画／图文对齐，失败降级文字 | 2s 降级 | 保持为底线 |
| 打断 | 事件优先／新意图打断 | 已有优先级表 | 保持 |
| 智能 | FAQ／NLP；部分接 LLM | 方案增 Agent 旁路 | 差异化点 |
| 运营 | 会话标记、评价分类型 | 已设计 | 落地待 POC |
| 限流 | 并发 Room／席位 | ≥30 Room 示例 | 配额待确认 |

## 3. 深度结论（推演）

1. **胜负手在「失败体验」与「解决率」**，不在形象个数。  
2. LLM 适合做编排与话术润色，不适合无闸门执行转人工／承诺。  
3. 与独立数字人直播／营销场景不同：客服场景必须可审计、可转人工。  
4. 本项目最优路径是 **寄生现网会话体系**，而非新容器。

## 4. 对方案的输入

- 架构不变、Agent 可关、图文降级强制 → 写入接入方案  
- 评价分类型、会话筛选 → 保留 MVP 需求  
- 披露非真人 → 设计／合规待确认
