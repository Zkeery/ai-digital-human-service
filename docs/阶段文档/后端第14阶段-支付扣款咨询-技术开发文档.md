# 后端第 14 阶段 · 支付与扣款咨询 · 技术开发文档

> **线路：后端。** 不上线、不查真支付／银行流水。  
> 前端开场加「支付问题」见 **前端第 13 阶段**。  
> 总览见 [咨询场景开发手册](咨询场景开发手册.md)。

## 一、目标（产品话）

用户遇到支付／扣款异常时，先分清类型，再给自助步骤或建议转人工：

1. **支付失败** → 换方式重试、检查限额等说明  
2. **重复扣款** → 保留凭证、建议转人工核对退回  
3. **已扣款未发货** → 先看订单／物流，异常则转人工  
4. 可点快捷选项  

与「退款」分流：本阶段不进入退货／退款进度话术，除非用户另说「退款」。

## 二、范围

### 做

| 项 | 说明 |
| --- | --- |
| 状态 | `payment_flow`：`idle`／`awaiting_clarify` |
| 触发 | 支付问题、支付失败、重复扣款 等（其它多轮进行中不抢） |
| 分支 | 支付失败／重复扣款／已扣款未发货／转人工 |
| 测试 | 澄清三分支；不抢退款／投诉进行中 |
| 关键文件 | `payment_dialogue.py` · `sessions.py` · 各对话 pack · `test_stage14_payment.py` |

### 不做

- 真查单、真退款到账、改支付通道  

## 三、状态机

```text
idle → 问支付问题 → awaiting_clarify
  ├─ 支付失败 → 重试指引 → idle
  ├─ 重复扣款 → 留证＋建议转人工 → idle
  ├─ 已扣款未发货 → 看订单／物流或转人工 → idle
  └─ 转人工 → 建议转人工 → idle
```

## 话术原则

- 先短问一句，细节交给选项或用户自述；**不要一长串枚举**  
- 分支回复也要短：承接 + 一两步动作即可，少公文腔、少复读选项名  
- 用户已点类型后，**不要复读**选项名当开头  

## 四、通过条件

1. 「支付问题」→ 澄清 + 选项  
2. 「重复扣款」→ `suggest_transfer_human` 为真  
3. 退款澄清中不抢答  
4. pytest 全绿
