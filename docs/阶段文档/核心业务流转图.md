# 核心业务流转图｜问答 · Agent · 降级 · 转人工

> 对应本机试点实现（联调页 http://127.0.0.1:8050/ · 前端 http://127.0.0.1:3050/）。  
> **业务线**：零售金融客服。行业多轮规则替换中；底座流转如下。  
> 「建议转人工」≠「已经转人工」：前者可由规则／Agent 提出，后者必须点转人工接口。  
> 资金／身份类操作不得由模型自主执行。

---

## 一、整段会话（鸟瞰）

```mermaid
flowchart TD
  A[用户从试点入口进入] --> B{入口是否白名单?}
  B -->|否| B1[拒绝建会话]
  B -->|是| C[创建会话 active]
  C --> D[可选：展示引导]
  D --> E[初始化数字人 Room]
  E --> F[用户发送一句话]
  F --> G[生成口播 + 动作意图 + 图文引用]
  G --> H[推流排队 queued]
  H --> I{约 2 秒内是否开始播?}
  I -->|是 stream-started| J[状态 started · 正常播报]
  I -->|否超时| K[2 秒同步降级 · 改看图文]
  J --> L{用户还要继续?}
  K --> L
  L -->|继续问| F
  L -->|点转人工| M[会话 transferred · 关 Room]
  L -->|评价后结束| N[结束]
  M --> N
```

## 二、一句话怎么变成口播（问答 + Agent）

```mermaid
flowchart TD
  U[用户文本] --> F{FAQ 能否命中?}
  F -->|命中| F1[记下 FAQ 答案作底稿]
  F -->|未命中| F2[准备规则兜底话术]
  F1 --> A{Agent 开关开着?}
  F2 --> A

  A -->|关| R1[直接用 FAQ 或规则兜底]
  A -->|开| AG[调用模型生成结构化 JSON]

  AG --> V{校验通过且未超时?}
  V -->|是| R2[采用 Agent 口播<br/>来源 source=agent<br/>可带「建议转人工」]
  V -->|否| R1

  R1 --> OUT[返回：口播 / 动作意图 / 图文引用<br/>agent_used=否]
  R2 --> OUT2[返回：同上<br/>agent_used=是]
  OUT --> SAVE[写入会话最近应答 + 历史]
  OUT2 --> SAVE
```

要点（产品话）：

| 情况 | 用户听到什么 |
| --- | --- |
| Agent 关 | 只走 FAQ／固定兜底，不花钱调模型 |
| Agent 开且成功 | 模型润色／生成口播；仍不能自己执行转人工 |
| Agent 开但失败／超时 | 静默跳过 Agent，退回 FAQ／兜底，会话不停 |

## 三、推流同步与「2 秒降级」

```mermaid
flowchart TD
  P[拿最近一条应答去推流] --> Q[指令进入队列 queued]
  Q --> W{等待开始播<br/>默认 hold ≈ 2000ms}

  W -->|客户端回报 stream-started| S[标记 started · 正常数字人播报]
  W -->|主动点「模拟超时」或 check-sync 超时| FB[记事件 dh_sync_fallback_2s<br/>指令标为 skipped]
  FB --> G[前端改展示图文／在线客服路径]

  S --> E{若正在播的是「事件」类指令?}
  E -->|是| BLK[期间禁止新的 NLP 口播打断]
  E -->|否| OK[可继续下一条问答推流]
  BLK --> EV[新事件可打断旧事件]
```

两种降级入口（效果同类）：

1. 联调页「模拟 2s 超时」→ 直接记降级事件  
2. `check-sync`：队列里还有 `queued` 且超过 hold → 自动降级

## 四、转人工（建议 vs 执行）

```mermaid
flowchart TD
  Q[用户表达要人工／投诉等] --> AG{本轮是否走了 Agent?}
  AG -->|是| SUG[Agent 可把 suggest_transfer_human=true<br/>口播可说「建议转人工」]
  AG -->|否| UI[页面仍可出现转人工入口]

  SUG --> C{用户／客服是否点「转人工」?}
  UI --> C

  C -->|否| STAY[会话仍是 active · 继续问答]
  C -->|是 调确定性接口| T[会话 status=transferred]
  T --> CL[关闭该会话数字人 Room]
  T --> EV[记事件 dh_transfer_human]
  T --> STOP[不能再发消息]
```

| 角色 | 能不能「真的转走」 |
| --- | --- |
| Agent／模型 | 不能，最多建议 |
| 转人工按钮／接口 | 能，改会话状态并关 Room |

特殊指令 `0002`（转接告知）属于**事件播报**，仍不等于执行转人工。

---

## 五、一条完整幸福路径（例子）

1. 白名单入口建会话 → 引导 → 初始化 Room  
2. 用户：「怎么退货？」→ FAQ／Agent 出口播  
3. 推流排队 → 2 秒内开始播 → 用户听数字人  
4. 若一直不开始播 → 降级看图文  
5. 用户：「转人工」→ 仅当点击转人工后会话关闭数字人支路
