# 后端第 9 阶段 · 发票开票咨询 · 技术开发文档

> **线路：后端。** 不上线、不接真实开票系统。  
> 前端开场加「开发票」见 **前端第 7 阶段**。

## 一、目标（产品话）

用户问发票／开票时，先分清需求：

1. **电子发票** → 自助开票路径说明  
2. **纸质发票** → 申请说明，可建议转人工  
3. **重开发票／改抬头** → 说明限制与转人工建议  

## 二、范围

### 做

| 项 | 说明 |
| --- | --- |
| 状态 | `invoice_flow`：`idle`／`awaiting_clarify` |
| 触发 | 发票、开票、发票抬头 等 |
| 快捷选项 | 电子发票、纸质发票、重开／改抬头、转人工 |
| 测试 | 澄清→电子；澄清→重开；与退货／物流互不抢答 |

### 不做

- 真实开票、税号校验、改后端其它流程  

## 三、状态机

```text
idle → 问发票 → awaiting_clarify
  ├─ 电子发票 → 电子话术 → idle
  ├─ 纸质发票 → 纸质话术 → idle
  ├─ 重开／改抬头 → 重开话术（可 suggest 转人工）→ idle
  └─ 转人工 → 建议转人工 → idle
```

## 四、通过条件

1. 「开发票」→ 澄清 + 选项  
2. 「电子发票」→ 自助说明  
3. 「重开改抬头」→ 限制说明且可建议转人工  
4. pytest 全绿  

## 五、验收（3050）

开场点「开发票」走完上述路径。
