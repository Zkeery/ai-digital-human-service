# 后端第 10 阶段 · 修改收货地址 · 技术开发文档

> **线路：后端。** 不上线、不接真订单改址接口。  
> 前端开场加「改地址」见 **前端第 9 阶段**。

## 一、目标（产品话）

用户要改收货地址时，先分清：

1. **还未发货** → 教在订单里改地址  
2. **已经发货** → 说明通常需拦截／转寄，建议转人工  
3. 可点快捷选项  

## 二、范围

### 做

| 项 | 说明 |
| --- | --- |
| 状态 | `address_flow`：`idle`／`awaiting_clarify` |
| 触发 | 改地址、修改地址、收货地址 等 |
| 分支 | 还没发货／已经发货／转人工 |
| 测试 | 澄清→未发货；澄清→已发货建议转人工；不抢退货流程 |

### 不做

- 真实改址、物流拦截 API  

## 三、状态机

```text
idle → 问改地址 → awaiting_clarify
  ├─ 还没发货 → 自助改址话术 → idle
  ├─ 已经发货 → 说明限制＋建议转人工 → idle
  └─ 转人工 → 建议转人工 → idle
```

## 四、通过条件

1. 「改地址」→ 澄清 + 选项  
2. 「还没发货」→ 自助说明  
3. 「已经发货」→ suggest_transfer_human=true  
4. pytest 全绿

开场点「改地址」走完路径。
