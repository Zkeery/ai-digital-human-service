# 前端第 3 阶段 · 技术开发文档

> 只覆盖本阶段。承接第 2 阶段已验收的访客／验收双模式。  
> **不上线、不接真 RTC／现网蒙层；不改后端业务契约**（前端展示与交互为主）。

## 一、目标（产品话）

让 **访客模式** 更像真客服结束态与评价体验，少露「开发信息」：

1. 访客对话区不展示 `source`／`agent_used`／图文模板技术字段；改成短状态（如「客服已回复」）。  
2. 「开始咨询」成功后，引导话术若有返回则进入对话气泡（无则用固定欢迎句）。  
3. 评价改为可选 1～5 星（默认 5），提交后有明确成功提示；转人工结束后展示结束卡片，输入区隐藏。  
4. 主题与访客／验收模式一并本地记住（`localStorage` 主题；模式仍 `sessionStorage`）。  
5. 忙碌态按钮文案（发送中／开始中），避免连点。

验收地址：**http://127.0.0.1:3050/**。

## 二、范围

### 做

| 项 | 说明 |
| --- | --- |
| 访客信息降噪 | `reply-meta` 仅 lab 可见；guest 会话 ID 可不展示或仅「咨询中」 |
| 引导入聊 | guest 开始咨询后写入一条 assistant 气泡（guide 返回或默认文案） |
| 评价 | 星级选择 + 提交；类型仍 `digital_human` |
| 结束态 | `transferred` 后展示结束卡（转人工成功），禁用并隐藏 composer |
| 主题持久化 | `localStorage.dh_ui_theme` = `default`｜`ink` |
| 忙碌文案 | 主按钮在 busy 时显示进行中文案 |
| 单测 | 结束态／访客是否展示 meta 的纯函数；原有 mode 测试保留 |
| 文档 | README、状态、证据包 |

### 不做

- 上线、登录、真数字人视频  
- 改 Agent／FAQ 后端逻辑  
- 新增多入口运营台  

## 三、通过条件

1. guest：开始咨询后聊天气泡可见欢迎／引导；发消息有回复；无技术 meta 行  
2. guest：评价可选星级并成功提示  
3. guest：确认转人工后见结束卡，无法再发消息  
4. 刷新后主题仍在；lab 功能不回退  
5. vitest／typecheck／build／后端 pytest 通过；证据包齐全  

## 四、验收清单（产品经理）

1. 访客开始咨询 → 看到欢迎／引导气泡  
2. 发「怎么退货？」→ 有回复，且看不到 source／Agent 字样  
3. 选星评价 → 成功提示  
4. 转人工确认 → 结束卡，不能再输入  
5. 换肤后刷新，主题还在  
6. 验收模式仍可开关 Agent、模拟降级  

## 五、完成定义

上表手测通过后宣布本阶段完成；未手测前为「开发完成待验收」。
