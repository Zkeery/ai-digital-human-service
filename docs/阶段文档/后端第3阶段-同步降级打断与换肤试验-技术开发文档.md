## 一、阶段目标

### 交付范围

在第 2 阶段契约桩之上补齐体验闭环与可观测性：

1. **有界会话历史**：每会话保留最近 N 条用户／助手摘要（默认 10），供 compose 与联调展示。  
2. **2s 同步自动降级**：推流入队后若超过 `SYNC_HOLD_MS` 仍未「开始展示」，可调用检查接口自动写入 `dh_sync_fallback_2s`（联调页可一键「检查超时降级」）。  
3. **打断优先级（桩）**：事件类指令在 **started** 状态时，NLP 推流返回 `BLOCKED_BY_EVENT`；新事件可打断旧事件（旧指令 `skipped`）。queued 欢迎语不阻挡 NLP 联调主路径。  
4. **特殊指令推送**：支持按白名单 `command_id` 直接入队（转人工播报 0002 等）。  
5. **联调页换肤试验**：提供 2 套主题（默认／深色点缀），仅影响验收页视觉，非正式产品皮肤包。  
6. **契约字段别名表**：代码内固化 jtalk／数字人字段映射说明接口，便于后续现网对账。

### 阶段产物

- 后端能力扩展（8050）  
- 联调页：历史、超时检查、特殊指令、换肤  
- mock 测试通过  
- `docs/evidence/后端阶段3/` + README／项目状态更新  

### 验收标准

- 多轮发话后可查到有界历史  
- 推流后不点「开始展示」，点「检查超时降级」可在超时后记降级（可用缩短 hold 测）  
- 欢迎语等事件未开始展示时，NLP 推流被阻止或标记 blocked  
- 可推送 0002 等特殊指令  
- 换肤切换后页面主题变化且刷新可恢复（localStorage）  
- 字段别名接口返回映射表  

### 明确不做

真引擎、现网 OpenAPI 终态对账编码、多入口、上线、RAG。

### 主链路片段

```text
多轮对话（写历史）→ 推流
  → 未开始展示且超时 → 自动／检查降级
  → 事件指令优先于 NLP
  → 特殊指令／换肤／字段别名可查
```

## 六、数据

### 新表 `message_history`

| 字段 | 说明 |
| --- | --- |
| id | 自增 |
| session_id | 会话 |
| role | `user`／`assistant` |
| text | 截断摘要（≤200） |
| created_at | 时间 |

推流指令表沿用；增加可选 `blocked_reason` 字段（或仅事件 payload）。

### 打断状态（内存＋DB）

- 指令 `status`：`queued`／`started`／`skipped`／`blocked`  
- 存在 `queued` 或 `started` 的事件类指令时，NLP 入队 → `blocked`

## 十一、验收清单

1. 强制刷新联调页
