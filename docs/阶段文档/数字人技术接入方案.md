# 数字人技术接入方案（汇报主文档）

> **文档性质**：方案级，供评审汇报。  
> **不承诺**：系统实现、联调、性能达标或正式上线。  
> **架构原则**：整体沿用服务数字人一期主链路；允许 C 端界面换肤；在应答编排处引入有界 AI Agent。  
> **业务线（2026-10-02）**：**零售金融客服**（非投顾、非电商售后）。  
> **版本**：V0.3｜2026-10-02｜项目：AI数字人客服  
> **口述版**：会上按 [数字人技术接入方案-汇报口述稿.md](数字人技术接入方案-汇报口述稿.md) 讲述（约 12–18 分钟）。

---

## 0. 摘要

本方案描述如何在 **jtalk 客服体系** 内接入／演进 **零售金融 AI 数字人客服 Agent**：

- **不变**：会话模型、分流控制、jtalk 转发 NLP、数字人 Room／RTC 推流、图文与口播同步、异常降级回图文。
- **可变**：C 端蒙层与对话区视觉／交互；应答侧由「固定话术＋FAQ」增强为「有界 Agent 生成口播稿＋动作意图」，仍经既有指令／配置落地。
- **边界**：数字人音视频引擎、RTC、TTS／CV 视为外部能力；本方案不承诺自研替换。

## 1. 系统边界

### 1.1 逻辑分域

```text
┌─────────────────────────────────────────────────────────────┐
│                        用户触点（C 端）                       │
│  jtalk H5/SDK 壳 │ 对话答案蒙层(可换肤) │ 数字人全屏蒙层(引擎) │
└─────────────┬───────────────────┬───────────────────┬───────┘
              │                   │                   │
              ▼                   ▼                   ▼
┌──────────────────┐   ┌──────────────────┐   ┌──────────────────┐
│  jtalk 前端/后端  │   │ 会话管理 / 分流   │   │ 数字人服务端      │
│  消息、会话、UI   │◄─►│ 入口/FAQ 开关     │   │ Room、推流指令    │
└────────┬─────────┘   └──────────────────┘   └────────┬─────────┘
         │ 转发 NLP 请求/答案                            │ TTS/CV/RTC
         ▼                                              ▼
┌──────────────────┐                         ┌──────────────────┐
│ NLP / FAQ / 机器人 │                         │ 数字人引擎/RTC   │
│ （现网能力）        │                         │ （外部能力）      │
└────────┬─────────┘                         └──────────────────┘
         │ 可选增强（方案级）
         ▼
┌──────────────────┐
│ AI 客服 Agent 编排 │  ← 本方案「新增逻辑槽位」：有界工具+结构校验
│ （可旁路开关关闭）  │
└──────────────────┘
```

### 1.2 职责矩阵

| 系统 | 负责 | 不负责 |
| --- | --- | --- |
| jtalk C 端 | 会话 UI、输入、评价、与数字人蒙层协作、同步超时降级 | 模型推理、RTC 媒体实现 |
| jtalk 后端 | 会话状态、转发 NLP、调用数字人 JSF／接口、分流配置读取 | TTS／形象渲染 |
| 会话管理／运营配置 | 数字人服务标记、入口数字人配置、FAQ 分流标记、口播／动作 ID | Agent 策略细节 |
| 数字人服务端 | Room 生命周期、下发口播／动作、监听 user 进出 | 业务 FAQ 决策 |
| 数字人引擎＋RTC | 形象渲染、音视频推流 | 客服业务规则 |
| NLP／机器人 | 意图与图文答案 | 推流与形象 |
| **AI Agent 编排（方案新增）** | 在授权范围内生成结构化口播文本／动作意图／是否转人工建议 | 直接推流、绕过分流、越权写生产数据 |

### 1.3 信任边界

1. **用户内容** → 仅进入 jtalk／NLP／Agent 输入通道；不得进入未授权的外部训练接口（待确认供应商合同）。  
2. **密钥** → 仅服务端；C 端与数字人蒙层不持有业务主密钥。  
3. **Agent** → 默认无开放 Shell／任意 URL；工具白名单见《Agent需求文档》。  
4. **数字人引擎** → 按现网隔离；初始化限流（基线：未销毁 Room≥30 拒接）仍生效。

## 2. 接口调用（方案级契约）

> 下列为评审用契约草案，字段名对齐基线 PRD 语义；**未与现网 OpenAPI 做字段级对账前不得编码。** 对账结果记为待确认。

### 2.1 初始化／绑定形象（jtalk → 数字人后端）

| 项 | 说明 |
| --- | --- |
| 时机 | 用户进入数字人蒙层／入口分流唤醒 |
| 必传 | `sid`（会话）、`dProfileKey`（形象 001–004）、`specialTag=init` |
| 语义 | 同一 `sid` 绑定形象，会话内不可变更 |
| 成功 | 返回／复用 `roomId`，前端加入 Room |
| 失败 | 见 §3.3 异常表 |

### 2.2 应答推流（jtalk → 数字人后端）

| 项 | 说明 |
| --- | --- |
| 时机 | NLP／Agent 产出图文答案后 |
| 载荷 | `content`（口播文本＋动作）、特殊指令标识、消息类型（NLP／事件） |
| 并行 | 图文模板透传 jtalk 前端，**hold** 至数字人「开始展示」通知或超时 |
| 约束 | 非 init 时若 Room 无 user：返回异常码，不重建 Room；延迟销毁策略沿用现网（基线 20min） |

### 2.3 特殊指令 ID（jtalk → 数字人）

沿用基线配置（示例，以现网为准）：

| 指令 | ID（基线示例） |
| --- | --- |
| 欢迎语 | 0001 |
| 转人工播报 | 0002 |
| 排队播报 | 0003 |
| 异常提醒 | 0004 |
| 账单卡片 | 0005 |

Agent **不得自造未登记指令 ID**；只能映射到配置表。

### 2.4 分流与配置查询

| 接口语义 | 调用方 | 说明 |
| --- | --- | --- |
| 入口数字人配置 | jtalk | 形象默认值、入口分流开关 |
| FAQ 数字人标记 | NOM／配置平台 → jtalk | 决定是否展示引导浮层／卡片 |
| 数字人配置查询 | jtalk／服务端 | 一期可固定 key，无需多数字人前台 |

### 2.5 Agent 编排接口（方案新增，可关闭）

建议形态（旁路）：

```text
POST /agent/v1/compose-reply
请求：session_id, user_utterance, faq_hit?, last_visible_messages[], allow_tools[]
响应：{
  "spoken_text": "...",      // 口播
  "action_intent": "...",    // 映射到动作配置
  "graphic_template_ref": "...", // 图文模板引用，非任意 HTML
  "suggest_transfer_human": false,
  "safety_flags": []
}
```

- 超时／校验失败 → **跳过 Agent**，回退现网 NLP／FAQ 答案。  
- 必须结构校验；禁止把模型原始 JSON 直推数字人。

### 2.6 评价与会话标记

- 会话管理增加「数字人服务＝是／否」筛选与展示（基线已有）。  
- 评价类型区分：数字人／人工／机器人；数字人评价需带口播与动作指令上下文（方案级）。

## 3. 交互流程

### 3.1 主成功路径（一期＋Agent 可选）

```text
用户进入 jtalk
  → 入口/FAQ 分流命中数字人
  → C 端展示引导（浮层或卡片，会话内一次）
  → 用户进入数字人蒙层
  → jtalk init：sid + dProfileKey → 创建/加入 Room → RTC 推流
  → 欢迎语指令 0001 播报
  → 用户语音/文本输入
  → jtalk 后端：会话管理 →（可选）Agent compose → NLP/FAQ 图文
  → 并行：数字人推流口播+动作 ∥ 前端 hold 图文
  → 数字人「开始展示」→ 展示图文
  → 多轮；可打断（见优先级）
  → 转人工 / 结束 / 离开
```

### 3.2 图文与口播同步

| 规则 | 基线 | 本方案 |
| --- | --- | --- |
| 前端收到图文后计时 | 2s 内未收到推流开始 → **直接展示图文** | **保持** |
| Agent 超时 | — | 计入同一用户等待预算，优先保同步降级 |

### 3.3 异常与降级

| 场景 | 处理 | 用户感知 |
| --- | --- | --- |
| 后端创建／加入 Room 失败 | 返回异常；弹窗重试／回在线客服 | 可重试 |
| 前端加入 Room 失败 | 弹窗加载失败，回在线客服 | 明确失败 |
| 模型调用超时（引擎侧） | 后端重试，用户无感（基线） | 无感；需监控 |
| 初始化限流（Room≥30） | 提示人多稍后再试 → 回在线客服 | 拒绝进入 |
| 模型渲染校验异常 | 告警，丢弃消息（基线） | 可能只见图文 |
| Agent 失败／越权 | 关闭本轮 Agent，走 NLP | 无额外弹窗（推荐） |
| 页面刷新 | 沿用 roomId＋init 口播 | 连续体验 |
| 会话内 H5 返回 | 特殊指令欢迎回来 | 引导语 |
| 跨 App 重进 | ≤20min 复用 Room；否则新建 | 可能重新欢迎语 |

### 3.4 打断优先级（数字人侧，保持基线）

1. 事件消息 ＞ NLP 消息  
2. 播报事件中：NLP 不可打断，需等事件结束  
3. 事件可打断事件（如欢迎语中点账单）  
4. 播报 NLP 中：事件可打断；新 NLP 亦可打断  

Agent 产出默认归类为 **NLP 类**，除非显式标记为已登记「事件指令」。

### 3.5 机器人 ↔ 数字人 ↔ 人工

- 不新增会话类型；机器人会话上打「数字人服务」标记。  
- 机器人→数字人：传递最后一条相关消息＋欢迎语指令 ID。  
- 数字人→人工：走转人工播报指令＋现网排队逻辑。

## 4. 部署方式（方案级）

### 4.1 推荐形态（与现网一致）

| 层级 | 部署建议 |
| --- | --- |
| jtalk 前端 | 现网发布管道；数字人相关 UI 可独立灰度皮肤包 |
| jtalk 后端／会话 | 现网集群；Agent 作为**可开关旁路服务**同机房部署 |
| 数字人服务端／引擎／RTC | 沿用现网或供应商托管；本方案不重部署 |
| 配置／NOM | 现网；分流与口播配置走变更单 |

### 4.2 灰度与切量（对齐基线一期）

1. 入口分流开关默认关 → 永不触发答案分流。  
2. 开关开 → FAQ 标记／入口引导逐步放量。  
3. Agent 旁路单独开关：默认关；仅白名单入口开启。  
4. 一键关闭 Agent 不影响数字人纯播报链路。

### 4.3 容量与限流（沿用＋标注）

- Room 并发上限、销毁延迟、初始化限流：**以现网数字人配额为准**（基线示例 30）。  
- Agent QPS／超时：建议 ≤ 数字人推流准备时间预算；具体数字 **待压测（非本批）**。

### 4.4 环境

| 环境 | 用途 |
| --- | --- |
| 开发／测试 | 可 mock 数字人推流，验证同步与降级（若未来 POC） |
| 预发 | 真实引擎小流量 |
| 生产 | 双开关（分流＋Agent）独立控制 |

本批 **不创建** 上述环境。

## 5. 数据流转

### 5.1 主数据流

```text
用户音/文
  → jtalk C 端
  → jtalk 后端（会话 ID、用户标识）
  → 会话管理（权限、分流、历史）
  → NLP/FAQ（图文模板）
  → [可选] Agent（spoken_text, action_intent）
  → 数字人服务端（口播+动作）→ TTS/CV → RTC → 数字人蒙层
  → 通知 jtalk 前端 → 展示图文
  → 会话存储（机器人消息＋数字人标记＋评价）
```

### 5.2 数据分类

| 类别 | 示例 | 存哪里 | 留存 |
| --- | --- | --- | --- |
| 会话元数据 | sid、数字人服务标记、形象 key | 会话管理 | 与现网客服一致（待确认） |
| 对话文本 | 用户话、图文答案、口播文本 | 会话消息 | 同左 |
| 媒体 | RTC 流、可能的录音 | 引擎／RTC 侧 | **待确认是否落盘**；默认按现网 |
| 配置 | 分流开关、指令 ID、口播动作 | 配置中心 | 变更审计 |
| Agent 轨迹 | 工具调用、模型用量 | 仅服务端日志／轨迹库 | 脱敏；密钥禁止入库 |
| 评价 | 类型、等级、理由 | 评价存储 | 运营分析 |

### 5.3 流转禁令

1. 数字人服务端 **不直连** NLP（保持 jtalk 转发）。  
2. C 端不落业务密钥；不把完整身份证号等写入 Agent 提示（需脱敏策略，待确认）。  
3. Agent 轨迹默认不进入对外报表；Badcase 导出需权限审批（方案级）。

## 6. 安全合规

### 6.1 原则

| 主题 | 方案要求 |
| --- | --- |
| 最小权限 | Agent 工具白名单；默认只读配置＋生成口播结构 |
| 人工确认 | 转人工、高风险指令必须走既有业务确认／系统动作，不交给模型自行执行 |
| 审计 | 分流变更、Agent 开关、评价与会话标记可追溯 |
| 隐私 | 客服对话属个人信息／可能含敏感信息；处理需符合公司客服数据规范 |
| 出境 | **默认国内处理**；任一供应商跨境须单独立项评估 |
| 内容安全 | 口播文本过现网内容安全策略后再推流（对接点待确认） |
| 密钥 | 仅环境变量／密钥系统；不进仓库、不进前端、不进文档正文 |

### 6.2 威胁与缓解（摘要）

| 威胁 | 缓解 |
| --- | --- |
| 提示注入诱导转人工刷屏 | 转人工走规则＋频控；Agent 仅建议 |
| 口播播放错误资费／承诺 | 结构校验＋关键话术白名单／人工审核配置 |
| Room 资源耗尽 | 保持初始化限流与销毁策略 |
| 日志泄露证件号 | 日志脱敏规范；禁止全文用户文档入日志 |
| 供应链（TTS/CV 厂商） | 合同与数据处理协议；可切换时保留图文降级 |

### 6.3 合规清单（评审用，非已完成证明）

- [ ] 数据处理协议覆盖数字人引擎与 RTC  
- [ ] 录音／视频是否存储、周期、访问角色书面确认  
- [ ] 用户告知（数字人客服身份披露）文案确认  
- [ ] 未成年人／特殊业务线额外限制（若适用）  
- [ ] 安全初审／隐私初审会议纪要  

本批只提供清单，**不代替**合规签字。

## 7. 前端界面改造范围（架构不变）

允许改：

- 对话答案蒙层视觉、字体、按钮区、满意度入口排布  
- 引导浮层／卡片文案与样式  
- 输入区语音／文本切换的交互细节  

不建议本阶段改：

- Room／RTC 协议、形象绑定规则、同步 2s 降级  
- 会话类型模型、分流开关语义  
- 数字人引擎内部渲染管线
