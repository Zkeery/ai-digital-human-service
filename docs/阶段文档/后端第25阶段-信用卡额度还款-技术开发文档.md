# 后端第 25 阶段 · 信用卡／额度／还款日 · 技术开发文档

> **线路：后端。** 不上线、**不查真额度、不批额、不代还款**。  
> 开场不铺入口；用户说到信用卡／额度／还款日等进入。  
> 总览见 [咨询场景开发手册](咨询场景开发手册.md)。  
> 业务线：零售金融客服（PRD V0.3）。

## 一、目标（产品话）

用户问信用卡相关时，先短问一句，再分流：

1. **查额度** → 自助入口短指引  
2. **还款与账单** → 还款日／应还／还款方式短指引  
3. **申请提额** → 说明走系统审核，客服无法改结果；异常转人工  
4. 可点快捷选项（≤5）

## 二、范围

### 做

| 项 | 说明 |
| --- | --- |
| 状态 | `credit_flow`：`idle`／`awaiting_clarify` |
| 触发 | 信用卡、额度、还款日、账单还款 等 |
| 分支 | 查额度／还款与账单／申请提额／转人工 |
| 关键文件 | `credit_dialogue.py` · `sessions.py` · 状态 pack · `test_stage25_credit.py` |

### 不做

- 真查额度／账单、代还款、承诺提额结果  

## 三、状态机

```text
idle → 问信用卡相关 → awaiting_clarify
  ├─ 查额度 → 短指引 → idle
  ├─ 还款与账单 → 短指引 → idle
  ├─ 申请提额 → 审核说明＋可转人工 → idle
  └─ 转人工 → 建议转人工 → idle
```

## 话术原则

- **准确**：菜单路径与能力边界说清楚；禁用「多半／一般／大概／我保证不了」  
- 提额：明确「银行系统审核，客服无法改结果」，不装作能批额  
- 不索要完整卡号／CVV  

## 四、通过条件

1. 「信用卡」／「查额度」→ 澄清或分支答 + 选项≤5  
2. 「申请提额」→ 说明系统审核、客服无法改结果  
3. 与既有金融多轮互不抢  
4. pytest 通过  

## 五、验收（3050）

手打「信用卡」→ 点「查额度」或「还款与账单」／「申请提额」。
