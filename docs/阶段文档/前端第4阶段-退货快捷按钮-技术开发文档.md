# 前端第 4 阶段 · 退货快捷按钮 · 技术开发文档

> **线路：前端。**  
> 承接后端第 6 阶段 `quick_replies`。不上线、不接真 RTC。

## 一、目标（产品话）

退货多轮时，对话下方出现可点按钮（如「尺码不合适」「想换货」）。  
点一下＝发那句话，少打字、少记关键词。

## 二、范围

### 做

| 项 | 说明 |
| --- | --- |
| 展示 | 有 `quick_replies` 时，在输入框上方显示按钮行 |
| 点击 | 用选项的 `text` 调现有发消息接口 |
| 清空 | 新回复若无选项则隐藏；转人工结束态不展示 |
| 类型 | `MessageReply` 增加 `quick_replies` |
| 测试 | 规范化／是否展示的纯函数单测 |

### 不做

- 改后端分流规则  
- 上线、登录、真数字人视频  

## 三、通过条件

1. 访客：怎么退货？→ 出现探因按钮  
2. 点「尺码不合适」→ 有针对性回复，并出现「想换货」等  
3. 点「确认退货」→ 出现操作步骤  
4. 普通闲聊无按钮；转人工后无按钮  
5. vitest／typecheck／build 通过  

## 四、验收清单（产品经理 · 3050）

1. 开始咨询 → 怎么退货？→ 看到按钮  
2. 点「尺码不合适」→ 再点「想换货」  
3. 新开一轮：点到「确认退货」→ 听到申请步骤  

## 五、完成定义

手测通过后完成。
