# 后端第 8 阶段 · 物流发货查询 · 技术开发文档

> **线路：后端。**  
> 不上线、不接真实物流接口。前端开场入口在 **前端第 6 阶段** 加「查物流」。

## 一、目标（产品话）

用户问物流／发货时，先分清：

1. **已经发货** → 教在订单里看物流轨迹（话术级，不查真单号）  
2. **还没发货** → 催发货／预期说明，可建议转人工  
3. 用 `quick_replies` 可点选项  

## 二、范围

### 做

| 项 | 说明 |
| --- | --- |
| 状态 | `logistics_flow`：`idle`／`awaiting_clarify` |
| 触发 | 物流／快递／发货／到哪了／查物流 等 |
| 分支 | 已发货查轨迹；还没发货催一下；转人工（仅建议） |
| 测试 | 澄清→轨迹；澄清→催发货；与退货流程互不抢答 |

### 不做

- 真实物流 API、改单号  
- 大改前端（仅第 6 阶段加开场按钮）  

## 三、状态机

```text
idle
  └─ 问物流／发货 → awaiting_clarify
        ├─ 已发货／查轨迹 → 轨迹话术 → idle
        ├─ 还没发货／催发货 → 催发货话术 → idle
        └─ 转人工 → 建议转人工 → idle（会话仍 active）
```

退货／退款多轮进行中不抢答；物流澄清中优先物流。

## 四、通过条件

1. 「查物流」→ 澄清 + 快捷选项  
2. 「已经发货查轨迹」→ 轨迹话术  
3. 「还没发货催一下」→ 催发货话术  
4. pytest 全绿  

## 五、验收（3050）

配合前端第 6：开场点「查物流」走完上述路径。
