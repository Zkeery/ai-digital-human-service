# 后端第 13 阶段 · 投诉引导 · 技术开发文档

> **线路：后端。** 不上线、不建真投诉工单。  
> 前端开场加「我要投诉」见 **前端第 12 阶段**。  
> 总览见 [咨询场景开发手册](咨询场景开发手册.md)。

## 一、目标（产品话）

用户要投诉时，先分清类型并安抚，再引导转人工（执行转接仍点页面「转人工」）：

1. **物流／快递问题** → 可先自助查物流，复杂则转人工  
2. **商品问题** → 可先退货／换货自助，严重则转人工  
3. **服务态度／其他** → 建议转人工优先处理  
4. 可点快捷选项  

投诉**不**直接改订单状态；只建议转人工，不自动执行转接。

## 二、范围

### 做

| 项 | 说明 |
| --- | --- |
| 状态 | `complaint_flow`：`idle`／`awaiting_clarify` |
| 触发 | 投诉、我要投诉 等（其它多轮进行中不抢） |
| 分支 | 物流问题／商品问题／服务态度／转人工 |
| 测试 | 澄清三分支；不抢退货／换货进行中 |
| 关键文件 | `complaint_dialogue.py` · `sessions.py` · 各对话 pack 同步 · `test_stage13_complaint.py` |

### 不做

- 真工单、短信催办、自动执行转人工  

## 三、状态机

```text
idle → 问投诉 → awaiting_clarify
  ├─ 物流问题 → 安抚＋可查物流／建议转人工 → idle
  ├─ 商品问题 → 安抚＋可退换／建议转人工 → idle
  ├─ 服务态度 → 致歉＋建议转人工 → idle
  └─ 转人工 → 建议转人工 → idle
```

## 话术原则

- 用户已点过类型后，**不要再复读**「商品问题／物流问题」当开头  
- 先致歉或承接，再给 **1～2 个可执行下一步**（自助词或转人工）  
- 短句、口语，避免公文腔叠道歉  

## 四、通过条件

1. 「我要投诉」→ 澄清 + 选项  
2. 「物流问题」→ 含转人工建议（`suggest_transfer_human`）  
3. 退货探因中说「投诉」不打断退货（或可接受：仅 idle 时响应；本阶段选 **进行中不抢**）  
4. pytest 全绿  

## 五、验收（3050）

开场点「我要投诉」→ 选一类 → 听到引导并可转人工。
