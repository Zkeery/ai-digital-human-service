# 后端第 24 阶段 · 登录／密码／验证码引导 · 技术开发文档

> **线路：后端。** 不上线、**不代客改密、不代收验证码**。  
> 开场不铺入口；用户说到登录不上／忘记密码／验证码等进入。  
> 总览见 [咨询场景开发手册](咨询场景开发手册.md)。  
> 业务线：零售金融客服（PRD V0.3）。

## 一、目标（产品话）

用户登录或密码遇阻时，先短问一句，再分流：

1. **登录不上** → 自查短指引  
2. **忘记密码** → 自助找回路径（不代改）  
3. **收不到验证码** → 常见原因＋转人工  
4. 可点快捷选项（≤5）

## 二、范围

### 做

| 项 | 说明 |
| --- | --- |
| 状态 | `auth_flow`：`idle`／`awaiting_clarify` |
| 触发 | 登录不上、忘记密码、验证码、账号锁定 等 |
| 分支 | 登录不上／忘记密码／收不到验证码／转人工 |
| 关键文件 | `auth_dialogue.py` · `sessions.py` · 状态 pack · `test_stage24_auth.py` |

### 不做

- 真改密、真解锁、代收／核验验证码  
- 索要用户密码、短信验证码原文  

## 三、状态机

```text
idle → 问登录／密码／验证码 → awaiting_clarify
  ├─ 登录不上 → 短指引 → idle
  ├─ 忘记密码 → 短指引 → idle
  ├─ 收不到验证码 → 短指引＋转人工 → idle
  └─ 转人工 → 建议转人工 → idle
```

## 话术原则

- 明确请用户走 App／网银自助；不要发密码／验证码给客服  
- 锁定账户优先转人工  

## 四、通过条件

1. 「登录不上」／「忘记密码」→ 澄清或分支答 + 选项≤5  
2. 「收不到验证码」→ suggest 转人工  
3. 与 account／transfer／card 互不抢  
4. pytest 通过  

## 五、验收（3050）

手打「忘记密码」或「登录不上」走完路径。
