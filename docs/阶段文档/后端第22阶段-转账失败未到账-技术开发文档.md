# 后端第 22 阶段 · 转账失败／未到账 · 技术开发文档

> **线路：后端。** 不上线、**不查真交易、不代客转账**。  
> 开场不铺入口；用户说到转账失败／没到账等关键词进入。  
> 总览见 [咨询场景开发手册](咨询场景开发手册.md)。  
> 业务线：零售金融客服（PRD V0.3）。

## 一、目标（产品话）

用户说转账有问题时，先短问一句，再分流：

1. **转账失败** → 常见自查短指引  
2. **对方没收到** → 留证、查流水／转人工  
3. **多久能到** → 不承诺时效，只说一般看渠道＋转人工  
4. 可点快捷选项（≤5）

## 二、范围

### 做

| 项 | 说明 |
| --- | --- |
| 状态 | `transfer_flow`：`idle`／`awaiting_clarify` |
| 触发 | 转账失败、没到账、转账没到、汇款 等 |
| 分支 | 转账失败／对方没收到／多久能到／转人工 |
| 关键文件 | `transfer_dialogue.py` · `sessions.py` · 状态 pack · `test_stage22_transfer.py` |

### 不做

- 真查交易、代发转账、承诺到账时间  

## 三、状态机

```text
idle → 问转账问题 → awaiting_clarify
  ├─ 转账失败 → 短指引 → idle
  ├─ 对方没收到 → 短指引＋转人工 → idle
  ├─ 多久能到 → 短说明＋转人工 → idle
  └─ 转人工 → 建议转人工 → idle
```

## 话术原则

- 澄清一句口语；不保证到账时效  
- 不收集完整卡号／密码  

## 四、通过条件

1. 「转账失败」／「没到账」→ 短澄清或分支答 + 选项≤5  
2. 「对方没收到」→ suggest 转人工  
3. 与 `account_flow` 互不抢（进行中不抢）  
4. pytest 相关用例通过  

## 五、验收（3050）

手打「转账失败」走完路径。
