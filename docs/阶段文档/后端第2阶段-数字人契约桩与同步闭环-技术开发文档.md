## 一、阶段目标

### 交付范围

在第 1 阶段会话／Agent／降级能力之上，打通**本地可测的数字人契约闭环**（仍不接真推流）：

1. **初始化绑定形象**：`sid`＋`d_profile_key`（001–004）→ 创建／复用 `room_id`；会话内形象不可变更。  
2. **Room 限流桩**：活跃 Room ≥ 配置上限（默认 30）时拒接，事件可查。  
3. **欢迎语／指令映射**：登记指令 ID（0001 欢迎、0002 转人工播报等）；Agent／动作只能映射到白名单，不得自造。  
4. **应答推流桩**：口播＋动作下发为「推流指令」记录；支持标记「开始展示」；与 **2s 图文 hold** 联动（超时仍走已有降级）。  
5. **Agent 编排独立接口**：`POST /agent/v1/compose-reply`（可关）；失败回退 FAQ。  
6. **引导仅一次**：会话内 `dh_guide_show` 最多一次。  
7. **评价**：提交评价（数字人／人工／机器人）并落事件；数字人评价可附带最近口播／动作上下文。

### 阶段产物

- 后端 API 扩展（仍端口 **8050**）  
- 联调页增加：初始化 Room、开始展示、评价  
- mock 自动化测试全过  
- 本阶段证据包 `docs/evidence/后端阶段2/`  
- README 更新验收步骤  

### 验收标准

- 未 init 不能推流；init 后可得 `room_id`  
- 同一会话二次 init 换形象被拒绝  
- Room 满员时 init 失败且有明确错误码  
- 推流指令只含白名单指令／动作  
- 发话 →（可选）compose → 推流桩 → 可点「开始展示」；超时可降级  
- 引导接口第二次调用不重复记「有效展示」或返回 already_shown  
- 评价写入后事件可查  
- 重启后 Room／评价／推流事件可恢复  

### 明确不做

真 RTC、真 TTS／CV、现网 JSF 对账编码、多入口、换肤包、RAG、上线。

### 本阶段打通的主链路片段

```text
建会话 → 展示引导（一次）→ init Room（形象）
  → 欢迎语指令桩
  → 用户发话 → FAQ／Agent compose
  → 推流桩（口播+动作）∥ 图文 hold
  → 开始展示 或 2s 降级
  → 评价／转人工
```

## 六、数据、资产与状态

### 新增／扩展表

| 表 | 字段要点 | 说明 |
| --- | --- | --- |
| `rooms` | `room_id`, `session_id`, `d_profile_key`, `status`(active/closed), `created_at` | 一会话一活跃 Room |
| `stream_commands` | `id`, `room_id`, `session_id`, `command_id`, `spoken_text`, `action_intent`, `status`(queued/started/skipped), `created_at` | 推流桩 |
| `sessions` 扩展 | `guide_shown` bool, `d_profile_key` 可空 | 引导与形象 |

### 指令白名单（本阶段）

| ID | 含义 |
| --- | --- |
| 0001 | 欢迎语 |
| 0002 | 转人工播报 |
| 0003 | 排队播报 |
| 0004 | 异常提醒 |
| 0005 | 账单卡片 |
| NLP | 普通口播（非事件指令，归 NLP 类） |

动作意图仍：`none|wave|nod|transfer_announce`；`transfer_announce` 推流时映射指令 0002。

### Room 状态

```text
（无）──init──► active ──close／转人工──► closed
```

## 七、API 设计

保留第 1 阶段 `/api/v1/*`。新增：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/sessions/{id}/guide` | 引导展示；首次记 `dh_guide_show` |
| POST | `/api/v1/sessions/{id}/digital-human/init` | body:`{d_profile_key}` → `room_id` |
| POST | `/api/v1/sessions/{id}/digital-human/push` | 将最近一次应答或显式口播推入推流桩 |
| POST | `/api/v1/sessions/{id}/digital-human/stream-started` | body:`{command_db_id}` 标记开始展示 |
| GET | `/api/v1/sessions/{id}/digital-human` | 查 Room＋最近推流指令 |
| POST | `/api/v1/sessions/{id}/rating` | body:`{rating_type, score, comment?}` |
| POST | `/agent/v1/compose-reply` | 独立 Agent 编排（受全局 Agent 开关） |

### 主要错误码（新增）

| code | 含义 |
| --- | --- |
| `ROOM_LIMIT_EXCEEDED` | 活跃 Room 达上限 |
| `PROFILE_LOCKED` | 会话已绑定形象，不可变更 |
| `ROOM_NOT_FOUND` | 未初始化数字人 |
| `INVALID_PROFILE` | 形象不在 001–004 |
| `INVALID_COMMAND` | 指令／动作不在白名单 |
| `COMMAND_NOT_FOUND` | 推流指令不存在 |

发话接口增强：成功应答可附 `push_ready: true`；联调页可一键推流。

## 十、测试要求

### mock（必须）

1. 引导首次成功、第二次 `already_shown`  
2. init 成功；非法 profile 失败  
3. 二次 init 换 profile → `PROFILE_LOCKED`  
4. 推高活跃 Room 至上限 → `ROOM_LIMIT_EXCEEDED`（可用临时调低 limit 测）  
5. 发话后 push → stream-started 状态变更  
6. compose-reply 在 Agent 关时跳过或明确 disabled  
7. 评价写入事件 `dh_rate`  
8. 转人工时 Room 关闭（status closed）

## 十一、验收清单（产品经理照着做）

1. `./start.sh`，打开 http://127.0.0.1:8050/ 并强制刷新  
2. ① 创建会话 → 点「展示引导」（第一次成功；再点应提示已展示）  
3. 选形象点「初始化数字人」，页面出现 `room_id`  
4. ② 发送话术 → 点「推流最近应答」→ 点「开始展示」  
5. （可选）不点开始展示，点「模拟 2s 降级」，事件里仍有降级记录  
6. 提交一条数字人评价，事件出现 `dh_rate`  
7. 转人工后，数字人状态为已关闭／不可再推流
