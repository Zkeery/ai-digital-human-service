# 后端第 11 阶段 · 取消订单咨询 · 技术开发文档

> **线路：后端。** 不上线、不接真取消接口。  
> 前端开场加「取消订单」见 **前端第 10 阶段**。

## 一、目标（产品话）

用户要取消订单时，先分清：

1. **还未发货** → 教在订单里取消  
2. **已经发货** → **先挽留**；用户坚持后再说拒收／退货，可建议转人工  
3. 可点快捷选项  

与「退货」分流：取消订单不直接进入退货操作步骤。

## 二、范围

### 做

| 项 | 说明 |
| --- | --- |
| 状态 | `cancel_flow`：`idle`／`awaiting_clarify`／`retaining` |
| 触发 | 取消订单、撤单 等（不含泛「退货」） |
| 分支 | 还没发货／已经发货（先挽留）／转人工 |
| 测试 | 澄清两分支；已发货先挽留；不抢退货探因 |
| 关键文件 | `backend/app/services/cancel_dialogue.py` · `sessions.py` · `backend/tests/test_stage11_cancel.py` |

### 不做

- 真实取消、改库存  

## 三、状态机

```text
idle → 问取消订单 → awaiting_clarify
  ├─ 还没发货 → 自助取消话术 → idle
  ├─ 已经发货 → 先挽留（retaining），不直接教取消
  │     ├─ 还是要取消 → 拒收／退货说明（可建议转人工）→ idle
  │     ├─ 商品有问题 → 引导售后／退货或转人工 → idle
  │     ├─ 先等等看 → 安抚等待 → idle
  │     └─ 转人工 → 建议转人工 → idle
  └─ 转人工 → 建议转人工 → idle
```

## 四、通过条件

1. 「取消订单」→ 澄清 + 选项  
2. 「还没发货」→ 自助取消说明  
3. 「已经发货」→ **先挽留**，口头不出现拒收／退货操作步骤；选项含「还是要取消」  
4. 再点「还是要取消」→ 才说明拒收／退货，可 suggest 转人工  
5. pytest 全绿
