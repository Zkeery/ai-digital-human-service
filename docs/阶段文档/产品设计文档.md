# 产品设计文档（0→1 方案稿｜架构复用）

> 方案级。配套：[数字人技术接入方案](数字人技术接入方案.md)  
> **业务线（2026-10-02）**：零售金融客服数字人（非投顾、非电商售后）。

## 1. 产品定位

面向**零售金融咨询用户**的 **数字人形象客服**：在 jtalk 内用音视频形象播报答案，并保留图文记录；运营可按入口／FAQ 灰度。对内演进点是把应答编排升级为 **有界 AI Agent**，对外是「金融数字人客服」。

## 2. 用户与场景

| 角色 | 诉求 |
| --- | --- |
| 终端用户 | 问账户／转账／卡片／密码／网点等，听懂下一步；必要时转人工 |
| 客服运营 | 配置分流、查看是否数字人服务、看评价 |
| 产研 | 在不拆主架构前提下增强智能与体验；守住金融合规边界 |

主场景：jtalk 会话中被分流进入数字人蒙层 → 多轮语音／文字（金融咨询）→ 结束或转人工。

**非目标场景**：电商退货物流售后；投顾荐股与收益承诺；代客执行转账／挂失／改密。

## 3. 信息架构（C 端）

```text
jtalk 页面壳
├── 引导：浮层 / 卡片（会话内一次）
└── 数字人模式
    ├── 数字人全屏蒙层（引擎提供，可换皮容器）
    ├── 对话答案蒙层（可换肤：历史、气泡、状态）
    └── 底部功能区（语音/文本、浮层按钮、评价）
```

## 4. 关键交互原则

1. **先可达再炫**：推流失败 2s 内必见图文。  
2. **身份披露**：界面标明数字人客服（文案待法务）。  
3. **可退出**：随时回在线客服／转人工路径可见。  
4. **少打断业务规则**：打断优先级遵循现网数字人侧规则。  
5. **换肤不换协议**：UI 改动不得破坏 Room 通知与 hold 逻辑。  
6. **金融安全**：资金与身份相关只给自助说明或转人工，不在对话里代操作。

## 5. 状态与反馈

| 状态 | 用户看见 |
| --- | --- |
| 初始化中 | 加载中；失败可重试／返回 |
| 播报中 | 形象口播；可按规则打断 |
| 同步等待 | 图文 hold；超时展示图文 |
| 限流 | 人多稍后再试 |
| Agent 思考（若开启） | 不额外制造第二套等待文案；并入现有加载／播报 |

## 6. 运营侧（一期最小）

- 入口：数字人配置、分流开关  
- 会话管理：数字人服务筛选与列展示  
- 消息：数字人口播类型展示（可播放文本）  
- 评价：类型＝数字人  

「数字人在线侧复杂后台」「统计需求」基线为暂无／后置，本方案同样后置。

## 7. 非目标（设计）

- 不做独立 App  
- 不在一期做多 Agent 团队协作 UI  
- 不做开放插件市场  
- 不做投资建议产品形态  

## 8. 走查说明

《项目文档》中的产品／工程／设计走查需 **有可点击实现** 后执行。本批仅提供走查清单草稿：

- 分流关／开、FAQ 有／无标记  
- 初始化失败四类弹窗  
- 2s 降级、打断优先级、刷新复用 Room  
- 转人工、评价提交  
- Agent 开关关时行为与现网一致  
- 金融话术：无收益承诺、无代客操作暗示
