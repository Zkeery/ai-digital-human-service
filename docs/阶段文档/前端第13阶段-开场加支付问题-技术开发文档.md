# 前端第 13 阶段 · 开场加支付问题 · 技术开发文档

> **线路：前端。**  
> 承接后端第 14 阶段。开场芯片上限由 8 调至 9，以容纳「支付问题」。不上线。  
> 总览见 [咨询场景开发手册](咨询场景开发手册.md)。

## 一、目标（产品话）

开场增加 **支付问题**：一点就发「支付问题」，进入支付／扣款澄清。

## 二、范围

### 做

| 项 | 说明 |
| --- | --- |
| 开场芯片 | `STARTER_QUICK_REPLIES` 增加「支付问题」 |
| 上限 | `normalizeQuickReplies` 最多 9 个（开场与后端芯片共用） |
| 点击 | `onSend("支付问题")` |
| 单测 | 含「支付问题」；上限断言如有则更新 |
| 关键文件 | `quickReplies.ts` · `quick-replies.test.ts` |

### 不做

- 改后端支付状态机  
- 真支付、收银台  

## 三、通过条件

1. 开始咨询可见「支付问题」  
2. 点后出现支付失败／重复扣款／已扣款未发货等选项  
3. vitest 通过  

## 四、验收清单（3050）

1. 开始咨询 → 看到「支付问题」  
2. 点「支付问题」→ 类型澄清  
3. 点「重复扣款」→ 听到留证与转人工建议（不复读「重复扣款非常抱歉」）  

## 五、完成定义

手测通过后完成。证据见 `docs/evidence/前端第13阶段/`。
