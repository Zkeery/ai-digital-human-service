> 电商版投诉样例见历史 [后端第13](后端第13阶段-投诉引导-技术开发文档.md)（已归档，不再作为现行需求）。

## 一、目标（产品话）

用户要投诉或说纠纷时，先短问一句，再分流：

1. **账户交易纠纷** → 留证说明＋建议转人工核对（本客服不查真账）  
2. **卡片额度相关** → 边界说明＋建议转人工或走官方自助  
3. **服务态度** → 致歉＋建议转人工优先处理  
4. 答完一项后追问其余项，选项保留（同第26／27）

投诉**只建议**转人工，不自动执行转接。

## 二、范围

### 做

| 项 | 说明 |
| --- | --- |
| 状态 | `complaint_flow`：`idle`／`awaiting_clarify`；`complaint_seen` 记录已答项 |
| 触发 | 投诉、我要投诉、纠纷、举报 等 |
| 分支 | 账户交易纠纷／卡片额度相关／服务态度／转人工 |
| 关键文件 | `complaint_dialogue.py` · `sessions.py` · 状态 pack · `test_stage28_complaint.py` |

### 不做

- 真工单、短信催办、自动执行转人工、查真账／改额度  

## 三、状态机

```text
idle → 问投诉／纠纷 → awaiting_clarify
  ├─ 账户交易纠纷 → 短指引＋追问 → 仍 awaiting_clarify
  ├─ 卡片额度相关 → 短说明＋追问 → 仍 awaiting_clarify
  ├─ 服务态度 → 致歉＋追问 → 仍 awaiting_clarify
  ├─ 三项都问过 → 收口 → idle
  ├─ 不用了／没有了 → 收口 → idle
  └─ 转人工 → 建议转人工 → idle
```

## 话术原则

- **准确**：能力边界清楚；禁用「多半／一般／大概」  
- 先承接／致歉，再给可执行下一步（留证或转人工）  
- **追问**：答完一项后追问其余标签；选项不立刻清空  
- 不自动转接  

## 四、通过条件

1. 「我要投诉」→ 澄清 + 选项≤5  
2. 任一分支持 `suggest_transfer_human`  
3. 点完一项后选项仍在且有「您还想咨询…」  
4. 与既有金融多轮互不抢  
5. pytest 通过（含准确度门禁）  

## 五、验收（3050／8050）

手打「我要投诉」→ 点「账户交易纠纷」→ 确认追问与选项 → 再点一项或「转人工」。
