# 后端第 12 阶段 · 换货咨询 · 技术开发文档

> **线路：后端。** 不上线、不接真换货接口。  
> 前端开场加「换货」见 **前端第 11 阶段**。

## 一、目标（产品话）

用户直接说「换货」时，不必先走退货探因：

1. 先问原因：尺码／发错／质量  
2. 按原因给换货或补发指引，可建议转人工  
3. 退货流程里已有的「想换货」分支保持不变  

## 二、范围

### 做

| 项 | 说明 |
| --- | --- |
| 状态 | `exchange_flow`：`idle`／`awaiting_clarify` |
| 触发 | 换货、想换货、申请换货 等（退货进行中不抢） |
| 分支 | 尺码不合适／发错货／质量有问题／转人工 |
| 测试 | 冷启动澄清；不抢退货探因中的换货 |
| 关键文件 | `backend/app/services/exchange_dialogue.py` · `sessions.py` · 各对话 pack 同步 `exchange_flow` · `backend/tests/test_stage12_exchange.py` |

### 不做

- 真实换货、改库存、物流拦截  

## 三、状态机

```text
idle → 问换货 → awaiting_clarify
  ├─ 尺码不合适 → 换货自助指引 → idle
  ├─ 发错货了 → 补发／换货指引 → idle
  ├─ 质量有问题 → 留证＋换货或转人工 → idle
  └─ 转人工 → 建议转人工 → idle
```

退货多轮进行中（`return_flow != idle`）时，本阶段不抢答；退货侧「想换货」仍走 `faq:return_exchange`。

## 四、通过条件

1. 「换货」→ 澄清 + 选项  
2. 「尺码不合适」→ 换货操作说明  
3. 退货探因中再说「想换货」仍走退货侧话术  
4. pytest 全绿  

## 五、验收（3050）

1. 开场点「换货」→ 见尺码／发错／质量  
2. 点「尺码不合适」→ 听到申请换货指引  
3. （对照）先「怎么退货？」→「尺码不合适」→「想换货」仍为退货侧换货话术
