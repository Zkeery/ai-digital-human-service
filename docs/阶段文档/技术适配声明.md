## 1. 产品形态判断

- **产品类型与核心任务**：jtalk 场景下的 **零售金融** AI 数字人客服——客户用语音／文字咨询账户／转账／卡片／密码等，数字人形象口播＋图文应答，必要时转人工；在现网主链路上增加**可关闭的有界 Agent 旁路**。  
- **核心交互**：**多轮对话** + **固定编排为主、Agent 可选旁路**（转人工／关服务／改分流／资金与身份操作不交给模型自主执行）。  
- **开发路径**：**后端先行**。理由：数字人 Room／RTC／TTS 为外部现网能力；本仓库首要交付是可测的 Agent 旁路服务与契约桩。  
- **当前说明**：底座已交付；行业话术由电商样例切换为金融（见 PRD V0.3 与咨询场景手册）。**不上线、不接计费云资源、不接核心账务。**

## 2. 采用的默认方案

| 方案 | 采用原因 |
| --- | --- |
| Python 3.12 + FastAPI | 手册默认后端；本机端口 **8050** |

| SQLite + 本地 `data/` | 会话事件／开关配置需重启可恢复；单机联调够用 |
| Git + 项目内 `.env` | 密钥外置（强制底线） |
| 模型：用户自备 Key，官方／兼容 SDK | D4：不锁厂商，须国内合规 |
| Web（Next.js + TypeScript + Tailwind）最小联调页 | 端口 **3050**；仅开关与模拟会话，非正式 C 端蒙层 |
| 现网数字人引擎契约桩 | D6：按现网接入；本仓库用接口契约／stub，不嵌入引擎密钥到前端 |

## 5. 强制底线检查

- **密钥与隐私**：✅ 计划通过——Key／引擎凭证只进项目 `.env`；前端不持有；日志不记完整用户咨询原文与密钥；数据国内、不训练（D7）
- **数据与任务可恢复**：✅ 计划通过——会话事件、Agent 开关、入口白名单入 SQLite；进程重启可恢复
- **输入输出校验**：✅ 计划通过——模型输出结构校验；失败有限重试；错误 `{"error":{"code","message"}}`
- **错误与日志边界**：✅ 计划通过——不泄露堆栈给客户端；降级路径可测
- **高风险动作**：✅ 计划通过——转人工执行、关服务、改分流由确定性代码；费用超 ¥500／月须人工确认
- **测试与真实模型验收**：mock 测试先行；真实 Key 由你提供后冒烟；D2 待样例打分不阻塞开工

## 产品经理只需确认三件事

1. **理解是否正确**：在 jtalk＋现网数字人主链路上，先做**本地／联调 MVP**——1 个白名单入口、Agent 可关、2s 降级可验证；**本阶段不上线**；不换引擎、不上 RAG。
2. **有没有多出来的费用／平台／范围**：无新增计费云资源；只用你自备的模型 Key；引擎／RTC 仍走现网或契约桩。
3. **被暂缓的能力是否影响下一阶段验收**：不影响。完整 C 端换肤、现网灰度、RAG、正式上线都不进阶段 2 验收。
