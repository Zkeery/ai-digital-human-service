## 一、阶段目标

### 交付范围

在本机打通「试点单入口 → 会话应答 → Agent 可关旁路 → 2s 图文降级事件 → 转人工执行与建议分离 → 重启可恢复」：

1. **入口白名单**：仅配置的 **1 个** `entry_id` 可建数字人会话；其他入口拒绝。  
2. **主路径应答**：规则／FAQ 命中则直接出口播＋图文引用（确定性）。  
3. **Agent 旁路（可关）**：开启时，在授权范围内生成结构化口播／动作意图／是否建议转人工；校验失败或超时则**跳过 Agent**，回退 FAQ／规则答案。  
4. **2s 降级**：提供接口记录 `dh_sync_fallback_2s` 事件（模拟 C 端超时回图文）。  
5. **转人工**：Agent 只可 `suggest_transfer_human`；真正转人工必须调确定性接口。  
6. **持久化**：配置、会话、消息摘要事件写入 SQLite；进程重启可查。

### 阶段产物

- 可运行后端（端口 **8050**）  
- 最小联调页（同端口静态页，非正式 C 端蒙层）  
- SQLite：`data/app.db`  
- mock 自动化测试通过  
- README 启动与验收步骤 + 证据包目录 `docs/evidence/后端阶段1/`

### 验收标准（对齐 PRD，本阶段细化）

- 非白名单入口无法建会话  
- Agent 关闭时，应答不走模型，仅 FAQ／规则  
- Agent 开启（mock）时，应答带结构化字段且口播非空  
- 可触发并查询到 2s 降级事件  
- 仅「建议转人工」不会改变会话为已转人工；调用转人工接口后状态变为已转人工  
- 重启后端后，配置与会话事件仍在  
- 效果打分 **待样例打分**（无真实 Key 时冒烟写「待验」）

### 明确不做

多入口运营台、RAG、RTC／Room 真推流、引擎联调、正式 jtalk 账号、云部署、统计大盘、口播动作配置后台、真实数字人形象渲染。

### 本阶段打通的主链路片段

```text
校验入口白名单 → 创建会话 → 用户发话
  → FAQ/规则优先
  →（可选）Agent 结构化旁路
  → 返回口播+动作意图+图文引用
  → 可标记 2s 降级 / 可执行转人工
  → 事件可查、重启可恢复
```

## 六、数据、资产与状态

### 持久化

SQLite（`DATA_DIR/app.db`）。重启后配置快照、会话、事件可恢复。

### 表

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `app_settings` | `key`, `value`, `updated_at` | `pilot_entry_id`、`agent_enabled` |
| `sessions` | `id`, `entry_id`, `status`, `created_at` | `status`: `active`／`transferred`／`closed` |
| `events` | `id`, `session_id`, `event_key`, `payload_json`, `created_at` | 埋点与审计（不含完整用户原文时可截断） |

### 状态机（会话）

```text
active ──transfer──► transferred
active ──close────► closed
```

Agent **不能**直接把状态改为 `transferred`。

## 七、API 设计

统一前缀 `/api/v1`。错误：`{"error":{"code","message"}}`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 健康检查 |
| GET | `/config` | 读试点入口、Agent 开关 |
| PUT | `/config` | 改 `agent_enabled`（确定性；不可改多入口） |
| POST | `/sessions` | body:`{entry_id}`；非白名单 → `ENTRY_NOT_ALLOWED` |
| POST | `/sessions/{id}/messages` | body:`{text}`；回应答结构 |
| POST | `/sessions/{id}/fallback` | 记录 2s 降级事件 |
| POST | `/sessions/{id}/transfer` | 执行转人工 |
| GET | `/sessions/{id}/events` | 事件列表 |

### `POST /sessions/{id}/messages` 响应（成功）

```json
{
  "session_id": "...",
  "spoken_text": "...",
  "action_intent": "none|wave|nod|...",
  "graphic_template_ref": "faq:xxx|agent:default",
  "agent_used": false,
  "suggest_transfer_human": false,
  "source": "faq|agent|fallback_rule"
}
```

### 主要错误码

| code | 含义 |
| --- | --- |
| `ENTRY_NOT_ALLOWED` | 非试点入口 |
| `SESSION_NOT_FOUND` | 会话不存在 |
| `SESSION_NOT_ACTIVE` | 已转人工或关闭 |
| `BUDGET_EXCEEDED` | 超月费用上限（真实调用） |
| `VALIDATION_ERROR` | 入参非法 |

### Agent 边界

- 工具白名单：本阶段 **无外部工具**（只生成结构化回复）。  
- 最大：单次请求内一次模型调用；超时 `LLM_TIMEOUT_SECONDS`。  
- 人工确认点：转人工执行、改 Agent 开关（改配置接口）。

## 八、Prompt 设计（Agent 开启且非 mock 时）

- **角色**：客服口播撰稿助手，不承诺未授权权益，不输出未登记动作。  
- **输入**：用户话术摘要、可选 FAQ 命中摘要。  
- **输出 JSON**：`spoken_text`, `action_intent`, `graphic_template_ref`, `suggest_transfer_human`, `safety_flags`。  
- **校验**：缺字段／口播为空／`action_intent` 非白名单 → 丢弃 Agent，走 FAQ／规则。  
- mock：固定可校验样例，不访问网络。

动作意图白名单（本阶段）：`none`, `wave`, `nod`, `transfer_announce`。

## 十、测试要求

### 第一层 mock（必须全过）

1. 健康检查 200  
2. 非白名单入口建会话失败  
3. 白名单入口建会话成功  
4. Agent 关闭：命中 FAQ 时 `agent_used=false`  
5. Agent 开启（mock）：`agent_used=true` 且结构合法  
6. 降级接口写入 `dh_sync_fallback_2s`  
7. 仅建议转人工不改状态；执行 transfer 后 `transferred`  
8. 重启后（新 DB engine／重连）会话与事件仍在  

### 第二层真实冒烟

- 有 Key 且 `LLM_MOCK=0`：一条真实咨询 → 结构合法口播。  
- 无 Key：**待验**，不得用 mock 冒充。

## 十一、验收清单（产品经理照着做）

1. 按 README 启动后端，浏览器打开 `http://127.0.0.1:8050/`  
2. 看到试点入口 ID；保持 Agent「关」，发一句 FAQ 内问题，有口播回复  
3. 打开 Agent「开」，再发一句，回复里能看出用了 Agent（或页面标明 Agent 已用）  
4. 点「模拟 2s 降级」，事件列表出现对应记录  
5. 点「转人工」，会话状态变为已转人工；再发话应失败或提示不可用  
6. 关掉终端再启动一次，刷新页面仍能查到刚才会话事件  
7. （可选）配真实 Key 后关 mock 再试一句——无 Key 则本项标「待验」
