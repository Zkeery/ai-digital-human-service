# 后端第 23 阶段 · 银行卡绑定／解绑／挂失引导 · 技术开发文档

> **线路：后端。** 不上线、**不执行绑卡／解绑／挂失**。  
> 开场不铺入口；用户说到银行卡／绑卡／挂失等关键词进入。  
> 总览见 [咨询场景开发手册](咨询场景开发手册.md)。  
> 业务线：零售金融客服（PRD V0.3）。

## 一、目标（产品话）

用户问银行卡相关时，先短问一句，再分流：

1. **怎么绑卡** → 自助入口短指引  
2. **解绑卡片** → 自助入口短指引  
3. **挂失引导** → 紧急说明＋强烈建议转人工／官方挂失入口（**不代办**）  
4. 可点快捷选项（≤5）

## 二、范围

### 做

| 项 | 说明 |
| --- | --- |
| 状态 | `card_flow`：`idle`／`awaiting_clarify` |
| 触发 | 银行卡、绑卡、解绑、挂失、借记卡 等 |
| 分支 | 怎么绑卡／解绑卡片／挂失引导／转人工 |
| 关键文件 | `card_dialogue.py` · `sessions.py` · 状态 pack · `test_stage23_card.py` |

### 不做

- 真绑卡、真解绑、真挂失、收集完整卡号  

## 三、状态机

```text
idle → 问银行卡相关 → awaiting_clarify
  ├─ 怎么绑卡 → 短指引 → idle
  ├─ 解绑卡片 → 短指引 → idle
  ├─ 挂失引导 → 紧急指引＋转人工 → idle
  └─ 转人工 → 建议转人工 → idle
```

## 话术原则

- 挂失场景优先催用户走官方／人工，不承诺已挂失  
- 不索要完整卡号、CVV、密码  

## 四、通过条件

1. 「银行卡」／「绑卡」→ 澄清或分支答 + 选项≤5  
2. 「挂失」→ suggest 转人工  
3. 与 account／transfer 互不抢  
4. pytest 通过  

## 五、验收（3050）

手打「银行卡」→ 点「挂失引导」或直接说「挂失」。
